# 完成第一个任务

第一次使用的目标不是让 wuu 立刻完成大型功能，而是确认三个基础环节：它进入了正确的
工作区、模型服务能够调用工具、你能够检查最终结果。

## 选择安全的工作区

在左侧栏的**工作区**区域选择**添加工作区 → 使用现有文件夹**。第一次建议使用：

- 一个可以重新克隆的代码仓库；
- 一个专门准备的测试文件夹；
- 或通过**新建空白项目**创建的目录。

工作区是文件和命令的主要边界。会话也按工作区组织；如果看到错误的文件或历史会话，
先检查当前选择的工作区。

## 先让 wuu 阅读

在目标工作区中新建对话，先发送一个只读任务：

```text
先阅读这个工作区，不要修改文件。说明它的用途、主要目录，以及可以怎样验证它。
```

检查回答中的目录、技术栈和验证命令是否符合预期。如果不符合，停止当前任务并确认
工作区；不要让 Agent 在错误目录里继续修改。

## 再交付一个小任务

一个容易成功的任务应包含四部分：

1. **结果：**你最终想得到什么。
2. **范围：**应该处理哪个页面、模块或文件。
3. **约束：**哪些行为、数据或接口不能改变。
4. **验证：**完成后应该运行什么检查。

例如：

```text
修复当前失败的测试。只修改与失败原因有关的代码，不做无关重构。完成后运行相关测试，
并告诉我修改了哪些文件、测试结果是什么。
```

对于较大的功能，可以先要求 wuu 调查并给出计划，确认方向后再让它实施。

## 观察执行过程

wuu 会在消息流中显示文件读取、搜索、编辑和命令执行等工具活动。工具活动用于了解
进度，但不能代替最终检查。

如果任务方向错误，可以立即停止当前回复，再补充约束。继续发送消息时，wuu 会保留
当前会话上下文。

## 检查结果

任务完成后至少检查：

- 最终回答是否明确说明完成内容和验证结果；
- `/files` 中是否只出现预期范围内的文件；
- `/diff` 中是否存在无关改动、调试代码或敏感信息；
- 测试、构建或其他验证是否真正运行并通过。

需要自己检查命令时，可以使用 `/terminal` 打开当前工作区的 shell。对于重要改动，
在提交或发布前仍应由人审查 diff。

## 添加附件

可以在桌面输入框中加入文件或图片，并在消息里说明希望怎样使用：

```text
参考这张截图检查当前界面，只修复明显不一致的地方。
```

附件只让当前任务能够读取对应内容，不会自动把原文件加入工作区。希望保留为项目成果
时，应明确要求写入工作区中的目标路径。

## 继续同一个会话

wuu 会保存会话。重新打开左侧栏中的会话即可继续，例如：

```text
刚才的实现方向正确，但不要改变现有 API。请调整后重新运行测试。
```

CLI 中可以查看和恢复会话：

```bash
wuu session list
wuu session show --last
wuu exec resume --last "继续完成并验证"
```

不需要保存自动化任务时使用 `--ephemeral`。归档只会隐藏会话；删除会移除已保存历史，
应谨慎使用。
