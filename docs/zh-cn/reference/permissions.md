# 权限模式

权限模式控制 Agent 能访问和修改哪些本地路径。桌面端可以在输入框旁的运行时菜单中
切换；CLI 可以使用 `wuu exec --permission-mode` 覆盖单次运行。

## 三种模式

| 模式 | 适合场景 | 行为 |
|---|---|---|
| 标准 `standard` | 日常项目任务 | 读写当前 runtime 注册的文件根，包括 Agent home、用户工作区和系统临时目录，并保留敏感路径和高风险操作防护 |
| 只读 `read_only` | 理解代码、调查和评审 | 保持相同读取范围，但拒绝文件修改 |
| 无限制 `unconfined` | 明确需要访问工作区外文件的可信任务 | 移除 wuu 的路径边界，允许当前系统用户有权执行的修改；敏感文件写入、应用自身凭据和输出脱敏保护仍然生效 |

没有明确理由时使用标准模式。只需要分析时使用只读。`unconfined` 应视为把当前登录
用户级别的本机权限交给 Agent，只对可信任务短时启用。

即使在 `unconfined` 下，以下保护也不会关闭：

- `.env`、SSH 私钥、凭据配置等敏感路径不能通过文件工具写入，也不能用 git
  暂存或提交；读取这些文件时，常见密钥格式的值会被打码后再交给模型；
- `~/.wuu`（或 `WUU_HOME`）下的应用凭据文件（`auth.json`、`credentials.json`、
  `remote.json`、`phone.json`）在任何模式下都不可读也不可写；
- 命令输出中的常见密钥格式始终脱敏。

## 系统权限与隔离

获准运行的子进程会继承 wuu 的系统身份、环境变量和网络能力。处理恶意仓库、依赖或
原生程序时，应使用 macOS 沙箱、容器、虚拟机或独立系统账号进行系统级隔离。

## CLI 示例

```bash
wuu exec --permission-mode read_only "解释这个仓库，不要修改文件"
wuu exec --permission-mode standard "修复测试并验证"
```

`wuu exec` 是非交互式入口，权限判断只有允许或拒绝，不会在脚本中弹出等待确认的对话框。

## 配置所有权

正常启动时，项目配置不能替换用户选择的权限模式。这样可以避免打开仓库时被项目文件
静默扩大本地权限。完整加载顺序见[配置模型](configuration.md)，更详细的风险边界见
[安全模型](security-model.md)。
