# Desktop Design Notes

这份文档只沉淀跨界面反复适用的设计决策和它们的理由。具体数值（时长、间距、颜色）以代码里的 token 声明为准，文档只指名字；一条规则如果只影响一个组件，它不属于这里。

## 主题与品牌气质

外观只有一根轴：`data-theme="light" | "dark"`，由持久化偏好（跟随系统/亮/暗）解析，preload 在首帧前同步 stamp 到 `<html>`。**没有第二根皮肤轴**——曾短暂存在 `data-skin`（火苗/工作双皮肤），后来判断"两者只差几个颜色时刻，不值得机制成本"，把火苗直接焊进底盘、拆掉整套 skin 机制。

火苗（这套气质）的设计哲学：**底盘极素，识别度只来自少数署名时刻**。背景是中性白/黑，墨阶、发丝线、投影、几何都不带风格；不加描边、不加偏移投影、不换底色——装饰读起来是"用力"，克制读起来才是"品质"（此前的奶油底、新粗野硬影、全局墨线描边三版都因此被否）。静态署名时刻只有三个：

1. 空状态问候——吉祥物 + 衬线标题（`turns.css` `.empty-home-mascot` / `--empty-home-title-font`）；
2. 一个饱和 accent——landing 朱红 `--wuu-accent`，承载发送键、侧栏活性标记、焦点环、`::selection`、链接；
3. 用户气泡的小尾角——形状细节（`.user-message` / `.chat-bubble--user` 的非对称 border-radius），不是描边。

动效侧另有少数署名时刻（见「动效 · 例外要有名字」）。超出这些清单的风格规则视为 bug；要新增需先回答：它的完成度能不能配得上现有的。

规则：

- 所有颜色一律走 CSS custom property。亮色值写在 token 声明处（`base.css` 与各组件文件顶部），暗色覆盖只写在 `theme.css`。这两层就是全部。
- 署名时刻的值直接住在 base/theme 与对应组件 CSS 里。新增组件 token 照旧只需补 `theme.css` 暗色映射。

## 动效

wuu 是生产力工具：动效唯一的职责是**解释状态变化**——反馈（你点到了）、方位（它从哪来）、连续性（它变成了什么）。拿不出这三个目的之一，就不动。整体节奏比常见产品略缓，靠强减速缓动保住响应感：招牌曲线把大部分位移压在前三分之一时间里完成，尾段只负责收束，所以"更从容"不等于"更迟钝"。

### 三个决策问题

给任何东西加动效前按顺序回答：

1. **该不该动**——频率门槛：用户一天触发上百次的交互（hover、切 tab、按键反馈）只配最快档或不动；键盘触发的操作永远不动画；循环动效（脉冲/呼吸/发光）默认禁止，只允许表达"正在进行中"（spinner、streaming 指示）。
2. **往哪动**——方向要有出处：元素从哪个方向来，就从哪个方向走（基准见下）；弹层沿弹出方向展开，`transform-origin` 指向触发点。
3. **动多久**——按元素重量选档（见节奏阶梯），不按手感随写数值。

### 动效语言

- **一条招牌缓动**（`--ease-out`）承担绝大多数动效；退场用 `--ease-in` 加速离开；`--ease-bounce` 只允许表情/点赞这类玩味瞬间，界面控件禁用弹跳与回弹。
- **进重出轻**：退场比进场更短、位移更小、允许轻微缩小——用户的注意力已经离开了。
- **属性预算**：只动 `transform` 与 `opacity`。布局属性（width/height/top/margin/padding）禁止参与动画；例外只有两类结构性过渡——侧栏/面板的 grid 列（过渡期间暂停消息流的尺寸测量与滚动校正，结束后统一对齐一次），以及 tab 条的宽度折叠（进场从零长出、关闭收拢让邻居平滑补位；实现上插值的是 max-width 上限而非 flex-grow，后者在 tab 被上限钳住时读作跳变——见 `TabMotion.ts` 与两条 strip 的 CSS 注释）。
- **幅度克制**：弹层位移约 4px、面板 18–28px，缩放起点不低于 0.98；动效解释变化所需之外的幅度都是噪音。

### 节奏阶梯

数值的唯一来源是 `base.css` `:root` 的 motion token（本文档不复述数值）：

- `--motion-fast`——指针反馈：hover、press、颜色/边框/阴影。永远是最快档，响应感住在这里，放缓预算不许花在这一档。
- `--motion-base`——菜单、弹层、内容替换、单元素一次性进出场。
- `--motion-slow`——结构性移动：侧栏、面板、折叠区。
- `--motion-slower`——大区域折叠/揭示。
- `--motion-spin`——活动 spinner 的统一转速，配唯一的共享 keyframe `wuu-spin`；不许再定义新的旋转 keyframe。

选档规则：拿不准往低档选；同一个手势里协同运动的元素（如侧栏 grid 与正文 padding）必须同档同曲线，否则会撕开。

### 集中管理与扩展

- **两层 token**：原始阶梯（唯一写死毫秒数的地方）→ 语义别名（`--menu-enter-duration` 这类；只有多个文件要共享一个节奏时才新建别名，否则直接用原始档）。组件 CSS 只引用 token，写字面量毫秒数视为 bug。
- **JS 与 CSS 单一来源**：JS 定时器经 `renderer/motion.ts` 的 `motionDurationMs()` 在调用时读同名 token——等待过渡结束的 `setTimeout` 因此永远与样式一致，也自动跟随减弱动效归零。不许在 TS 里另写毫秒常量。
- **例外要有名字**：不走阶梯的动效只有两类——署名时刻（composer ultra 启动序列、launch glass 等，整段成套设计）和带注释的钉住值（信息面板）。没有名字和注释的裸数值不算例外，算欠账。

### 中断与状态连续性

- 可被反复触发、中途反悔的状态变化用 **transition**（可从当前值中断重定向）；一次性进出场才允许 keyframes。
- 点击必须立即进入目标状态，动画只解释变化——数据切换和可操作性不等动画结束。
- **有进必有出**：面板与弹层成对设计进出场；退场期间元素保持挂载（closing 状态机），卸载计时通过 motion.ts 读 token，与 CSS 时长天然同步。

### 基准动画

信息面板（environment panel）的进出场是全应用的质量标尺，其 token 值被钉住、不随阶梯调整（`base.css` 注释处）。它做对的四件事，新面板动效照着校准：从右侧减速滑入；退场沿原方向加速离开；退场更短；退场带轻微缩小。

由此推广的判例：**全屏接管类过渡用「片层」，不用网格挤压**。让一块面板占据整个窗口时，把它提升为以最终尺寸排版的整层（transform 滑动，内容零逐帧重排），台下布局原地不动等待揭示；不要让网格各列同时插值——那会使正文逐帧换行、面板内容逐帧重排，读作"布局被压扁"而非"面板上台"（右侧面板全局化 `data-sheet` 就是这个模式，见 `sidebar.css`）。

### 减弱动效

- `prefers-reduced-motion: reduce` 下 `base.css` 全局把阶梯 token 归零——token 驱动的动效自动即时化，新增动效走 token 即免费获得该行为。
- spinner 保持转动：它表达"正在进行中"，不是装饰。
- 手写本地时长的 keyframes（署名时刻、氛围循环）必须在定义处配同媒体查询关闭。
- JS 侧统一用 `motion.ts` 的 `prefersReducedMotion()`，不自建 `matchMedia`。

## 菜单

wuu 的菜单应该像轻量控件，而不是卡片或弹窗。它们服务于当前任务附近的快速选择，例如选择项目、切换模型推理档位、切换分支，或查看一句权限说明。

默认菜单规则：

- 面板使用紧凑规格：`12px` 圆角、`6px` 内边距、轻边框。
- 常规菜单项 `34px` 行高，行间距 `1px`，hover 状态要轻。
- 图标 `15px`–`17px`；宽度优先落在 `224px`–`300px`，只有内容确实需要时才加宽。
- 内容可能变长时设高度上限并允许滚动，不让菜单占据大片屏幕。
- 进场用共享的 `menu-enter`（`--menu-enter-duration/easing`）：opacity + 小幅 `translate3d` + 轻微缩放，向上弹出从底边展开、向下从顶边展开。标准菜单不做级联、不做弹跳（见「动效」）。

不要把菜单做成卡片或对话框。重阴影、大内边距、大行高和过宽面板，会让重复使用的控件显得笨重。

新增 dropdown、menu 或小 popover 时：先复用现有菜单变量和 `menu-enter`；选能保证文字可读的最窄宽度；按实际弹出方向设 `transform-origin`；内容会增长时加高度上限。只有界面职责不同（dialog、inspector、常驻侧栏）才新建另一套视觉规格。

## 消息流节奏

消息流的空白是一套固定用途的节奏。相邻元素要么靠近表达"同组"，要么留出明确边界；不要把多个局部间距叠成无法解释的死空间（历史教训：不可见但占位的 hover 操作行曾把 turn 边界撑到 60px）。

当前阶梯（token 声明在 `conversation-shell.css`，边界值在 `turns.css`；14px 正文下实机校过一轮，更小的一版被判过密）：

- 段内：行高 `1.75`（正文 prose 测度已限制在消息最大宽度内）。
- 工具行之间：`9px`（`--conversation-activity-gap`）；commentary 紧跟它引出的工具组时也收到 `9px`。
- 块之间：`18px`（段落、fold 内条目、answer 内块共用 `--conversation-prose-block-gap` / `--conversation-message-element-gap`），对行内空隙约 1.7 倍——低于这个比例段落就不成块。
- 结构交接：`16px`（发丝线 → process、process 折叠行 → 最终答案）。
- 节标题上方：块间距 + `12px`（`.rich-heading`）。
- 问 → 答：`24px` + 发丝线 + `16px`（发丝线负责解释这段空白）。
- turn 边界：`24px` 干净空白（`.turn` margin-bottom）。

配套规则：

- hover 操作行一律 overlay，不占流内空间；只有最新一条答案的常驻操作行例外（真实可见才配占位）。overlay 画进 turn 边界带，`.turn:hover/:focus-within` 时解除 `content-visibility` 的 paint containment（详见 `turns.css` 注释）。
- 正文层级停在"低语"级：标题 = 同字号 semibold + 上方额外空间（单一层级，不还原 h1-h6 字号）；`**bold**` = `--weight-medium`。要么全平（灰墙、无锚点），要么字号跳变（文档感、太吵），都被否过。
- 答案 prose、reasoning 与用户气泡共用一把测度尺（`--conversation-message-max-width`）；工具行和卡片仍然可以占满内容列。
- 过程区在只有 commentary、reasoning 或工具活动时保持展开，标题使用"正在处理"。第一段非空且确认的 `final_answer` 到达时立即进入回答交接：过程详情收成一行、旧过程预览不再重复显示，标题改为"正在回复"，最终答案开始占据主阅读位置。turn 完成时只把这一行改成"用时 …"，不再发生第二次收缩。
- 用户在回答交接后手动展开过程区时，本轮保持展开；自动状态变化不得抢回控制权。失败、中止或没有 `final_answer` 的 turn 不触发回答交接。

## 排队消息

排队消息（queue）和引导消息（guide）是 composer 的内部内容，不要在外面另起卡片。

默认规则：

- 队列直接放在 `.composer-shell` 内部、attachment strip 之上，宽度自然等于输入框。
- 每条占满壳子宽度，行间用 `1px` hairline 分隔，**不要**用大圆角、阴影或独立背景。
- 行内最多 3 个区域：位置序号、预览文本（单行截断）、动作区。动作区只保留两个按钮：删除（`X`）和 `…` 菜单。删除按钮常驻，菜单按钮可隐藏到 hover/focus-within。
- 序号用 `11px` 以下的 dim 灰、`tabular-nums`，不要做成 badge 或 dot。
- guide 状态不要用单独的图标行——用 row 文字色变化（`--turn-warning-text`）表达"已经是引导"即可。
- 行 hover 用低于 5% 的浅灰覆盖，不要换背景色。
- 队列本身已经是计数，**不要**再在 toolbar 上重复"已排队 N 条"这种 badge。
- 队列容量是异常情况，先不限制高度；超长时再考虑加 `max-height + 内部滚动`，不要默认就滚动。
