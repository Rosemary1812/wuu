# Desktop Design Notes

这份文档记录桌面端已经形成共识的设计规则。只写会反复影响多个界面的规则，不写临时想法，也不把它扩成大而全的设计系统。

## 主题与皮肤

外观有两根正交的轴，都以属性形式打在 `<html>` 上，preload 在首帧前同步 stamp：

- `data-theme="light" | "dark"`：亮暗轴，由持久化偏好（跟随系统/亮/暗）解析而来。
- `data-skin="flame" | "work"`：风格轴。`flame`（火苗）是默认皮肤，暖奶油纸面 + 朱红 `#ff3d00`，与吉祥物、landing 页同一气质；`work` 是安静的素色界面。

规则：

- 所有颜色一律走 CSS custom property。亮色值写在 token 声明处（`base.css` 与各组件文件顶部），暗色覆盖只写在 `theme.css`——这两层就是 work 皮肤，work 不需要任何自己的 CSS。
- 火苗皮肤只存在于 `styles/skin-flame.css`，且只允许覆盖 token，不允许出现组件选择器（有契约测试盯着）。两个块 `:root[data-theme="light"][data-skin="flame"]` / `:root[data-theme="dark"][data-skin="flame"]` 靠特异性压过 base 与 theme.css，与导入顺序无关。
- 皮肤没覆盖的 token 自动落回 work 同一亮暗档的值，所以新增组件 token 时照旧只需补 `theme.css` 暗色映射；只有当该 token 承载明显的冷暖色相时才考虑进 skin-flame.css。
- 组件要做"皮肤才有"的装饰（如空状态吉祥物），在组件 CSS 里声明一个默认关闭的 hook token（如 `--empty-home-mascot-display: none`），由皮肤翻开。组件本身保持对皮肤无感知。

## 菜单

wuu 的菜单应该像轻量控件，而不是卡片或弹窗。它们服务于当前任务附近的快速选择，例如选择项目、切换模型推理档位、切换分支，或查看一句权限说明。

默认菜单规则：

- 面板使用紧凑规格：`12px` 圆角、`6px` 内边距、轻边框。
- 常规菜单项使用 `34px` 行高。
- 行间距保持 `1px`，hover 状态要轻。
- 菜单里的图标控制在 `15px` 到 `17px`。
- 宽度优先落在 `224px` 到 `300px`，只有内容确实需要时才加宽。
- 内容可能变长时设置高度上限并允许滚动，不让菜单占据大片屏幕。
- 新菜单先使用 `styles.css` 里的共享菜单变量，不要随手写一套局部数值。

不要把菜单做成卡片或对话框。重阴影、大内边距、大行高和过宽面板，会让重复使用的控件显得笨重。

## 动效

菜单动效只负责让界面有响应感，不应该抢注意力。

默认菜单进场动效：

- 时长约 `140ms`。
- 缓动使用快速 ease-out，目前是 `cubic-bezier(0.16, 1, 0.3, 1)`。
- 属性只使用 opacity、小幅 `translate3d` 和从 `0.985` 到 `1` 的轻微缩放。
- 位移距离约 `4px`，避免大幅滑动。
- 向上弹出的菜单从底边展开；向下弹出的菜单从顶边展开。

标准菜单不要使用弹跳、回弹、长淡入或逐项级联动画。这些动效会让日常控件显得过重。

## 减弱动效

所有共享动效都必须尊重 `prefers-reduced-motion: reduce`。

菜单在减弱动效模式下直接关闭进场动画。以后新增控件动效时，也应该在同一个媒体查询下关闭动画，或改成即时状态变化。

## 新增弹出层

新增 dropdown、menu 或小 popover 时：

1. 先复用现有菜单变量和菜单进场动画。
2. 选择能保证文字可读的最窄宽度。
3. 根据实际弹出方向设置 `transform-origin`。
4. 内容会增长时加高度上限。
5. 只有当界面职责不同，例如 dialog、inspector 或常驻侧栏，才新建另一套视觉规格。

## 排队消息

排队消息（queue）和引导消息（guide）是 composer 的内部内容，不要在外面另起卡片。

默认规则：

- 队列直接放在 `.composer-shell` 内部、attachment strip 之上，宽度自然等于输入框。
- 每条占满壳子宽度，行间用 `1px` hairline 分隔，**不要**用大圆角、阴影或独立背景。
- 行内最多 3 个区域：位置序号、预览文本（单行截断）、动作区。动作区只保留两个按钮：删除（`X`）和 `…` 菜单。删除按钮常驻，菜单按钮可隐藏到 hover/focus-within。
- 序号用 `11px` 以下的 dim 灰、`tabular-nums`，不要做成 badge 或 dot。
- guide 状态不要用单独的图标行——用 row 文字色变化（`--turn-warning-text`）表达"已经是引导"即可。
- 行 hover 用 `rgba(31, 35, 40, 0.035)` 这种低于 5% 的浅灰，不要换背景色。
- 队列本身已经是计数，**不要**再在 toolbar 上重复"已排队 N 条"这种 badge。
- 队列容量是异常情况，先不限制高度；超长时再考虑加 `max-height + 内部滚动`，不要默认就滚动。
