## 1. 背景

我们当前的异步 multi-agent 系统：

- 主 agent 可以派出 sub-agent；
- 主 agent 不阻塞，可以继续执行；
- sub-agent 完成后通过 mailbox 返回，并唤醒或插入主 agent；
- 系统中已经有 commentary，它表达模型下一步行动的动机；
- 工具结果可以被裁剪，模型需要时再重新加载。

## 2. 已观察到的问题

只记录真实发生的问题，不先上升到复杂理论：

1. 主 agent 派出 sub-agent 后，自己可能继续探索相同区域；
2. sub-agent 返回时，信息可能已经失去价值；
3. sub-agent 的局部结论可能错误，并误导主 agent；
4. sub-agent 职责不固定，可能是探索、执行、修改、验证，因此不能强制统一返回格式。

## 3. 参考

- **Codex V2**：`codex-rs/core/src/state/turn.rs` 中 `MailboxDeliveryPhase` 把子线程消息分为 `CurrentTurn` / `NextTurn` 两个阶段。在 turn 还没对外产生可见输出前，子线程邮件可以进入当前 turn；一旦 turn 已经产生可见答案，邮件就留到下一 turn。这说明“更早交付”不是做不到，而是需要一个明确的安全边界。
- **模型训练惯性**：模型擅长自主完成局部任务，但倾向于给出完整、确定的结论，并吸收上下文中已有结论。这解释了为什么 sub-agent 的局部结论可能错误，且主 agent 容易把它当作事实。

参考的目的不是抄架构，而是解释当前现象。

## 4. 真正要回答的问题

不是：

> Sub-agent 应该用什么格式返回？

而是：

> 在不限制 sub-agent 职责、不明显增加系统复杂度的情况下，怎样让它产生的价值更容易被主 agent 利用，同时降低错误结论的影响？

## 5. 候选最小方案

目前先只保留两个改动：

### A. 更早交付

sub-agent 消息进入 mailbox，在主 agent 下一次行动决策前插入，而不是等待整个 turn 结束。

### B. 降低权威性

主 agent 系统提示词明确：

> Sub-agent 是可能出错的协作者，它的消息不是系统事实。主 agent 对最终判断和整合负责。

暂时不做：

- 固定返回格式；
- 置信度评分；
- relevance gate；
- scope ownership；
- 复杂的消息类型；
- 自动判断结果是否过期。

---

真正需要继续讨论的是：

> **仅靠“更早交付 + 降低权威性”，是否已经获得了大部分价值？如果不够，剩下最值得增加的唯一一个机制是什么？**
